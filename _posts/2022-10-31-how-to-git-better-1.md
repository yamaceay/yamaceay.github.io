<p>… so you can be a more decent human being in the next projects :-)</p><p>In the following article, we will learn the most basic commands of Git using visualizations.</p><h4>Setup Your Local Repository</h4><p>In the next step, you can create a local repository as follows:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*MYXRRbpM6QfOwV2-sXWAVg.png" /></figure><p><code>git init</code>: Create a new repository on your local machine</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*HsVPTEJorS-mNUyUgltj-g.png" /></figure><p><code>git clone &lt;URL&gt;</code>: Save the copy of a remote repository</p><p>Now, let’s proceed with the most basic Git commands.</p><h4>Learn Git Definitions (If You Didn’t)</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*bWZXdqTZLjiZu4_8Um4xnw.png" /></figure><p>A <em>commit</em> is a set of changes which together make sense. It is usually an incremental update.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*MtTV33Hf89uEB0_daWFWLA.png" /></figure><p>A <em>branch</em> is an isolated workflow of a developer or a feature workflow which contains a list of commits. It is either a copy of another branch or the main branch itself.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*a1hGMK2KWXSiVHtbvi4mZQ.png" /></figure><p>A <em>tag</em> or <em>version</em> is the current status of a branch regarding functionality. Typically, each version consists of <em>major</em>, <em>minor</em> and <em>revision</em>. Depending on the importance of the commit, the major / minor / revision is incremented.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*mXiFtJbX-iFnVs-0gbgVCQ.png" /></figure><p>Let’s differentiate 3 types of local changes:</p><p><em>Unstaged changes</em>: This is what happens when you save the changes of a file using CTRL+S. The changes have to be staged, so that they can be included in a commit.</p><p><em>Staged changes</em>: These changes are marked as ready to be committed.</p><p><em>Committed changes</em>: The file changes are not in the staging area anymore, they are already packed into a commit.</p><h4>Staging ( and Unstaging) Changes</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*QyA3QJDaLoZaaPdUACgHvg.png" /></figure><p>You can use the following commands to work with the staging area:</p><p><code>git status</code>: See all staged and unstaged changes in your local.</p><p><code>git add &lt;path&gt;</code>: Stage a file change.</p><p><code>git reset &lt;path&gt;</code>: Unstage a file change.</p><h4>Committing (and Uncommitting) Changes</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*ztb-fF84GnsAwzgeu96nhQ.png" /></figure><p><code>git commit -m &quot;&lt;message&gt;&quot;</code>: Commit staged changes.</p><p><em>Note</em>: Working with commits is slightly different, especially when undoing a commit, because it affects the commit history.</p><p>There are two main reasons of uncommitting:</p><p>Either you want to make a reverse commit on top of your latest commit, or you want to remove the commit directly from the history.</p><p><code>git revert &lt;commit&gt;</code> : Make a reverse commit.</p><p><code>git reset &lt;commit&gt;</code> : Undo a commit and delete it from the history, leave undone changes unstaged. If used with option <code>--hard</code>, it will discard changes.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*yxw2IplSrAbx3MXf-CDOMA.png" /></figure><p><em>Note</em>: Before committing anything, make sure you have configured your name and email address, so that people can see who has made the commits.</p><p><code>git config user.name &lt;username&gt;</code>: sets your username</p><p><code>git config user.email &lt;email&gt;</code>: sets your email address.</p><p>If you use the same information in all projects, then add <code>--global</code> at the end of both commands.</p><h4>Ignoring Changes</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*tqQtCDjCCcEJWFFCoXJ4Fg.png" /></figure><p>There may be many reasons not to include a file in a remote repository, for example it can be a confidential file, it can be too large etc.</p><p>In this case, you have to write down the names of the files or file patterns in a new file called <code>.gitignore</code>.</p><p>Then you stage the file using <code>git add .gitignore</code>, so that the staged files with sensitive information are excluded from the staging area.</p><p>An example of <code>.gitignore</code> file:</p><pre><code>&lt;file&gt;
*.&lt;ext&gt;
&lt;filename&gt;.*
&lt;directory&gt;/</code></pre><h4>Stashing ( and Unstashing) Changes</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*oW2bbNTCNRwTEsO4eAV1TQ.png" /></figure><p>For some operations to properly work (as we will see in the next article), uncommitted changes have to be moved away temporarily.</p><p>A <em>stash</em> is a temporary commit including changes to be moved back into the staging area and it is stored in a stack.</p><p><code>git stash</code>: Add the uncommitted changes on top of the stack.</p><p><code>git stash list</code>: List all stash commits.</p><p><code>git stash pop</code>: Pop latest stash commit from the top of the stack and add the new changes as unstaged changes.</p><p><code>git stash drop</code>: Delete the stash commit on
