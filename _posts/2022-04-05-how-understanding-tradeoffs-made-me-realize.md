<blockquote>that a best solution for any problem is only best due to the circumstances. How to define best, if we actually don’t know, how to define good or bad?</blockquote><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*JfqDp7pvIMTuacgFe88dew.png" /><figcaption>Source: Bhavesh Bhatt</figcaption></figure><p>Tradeoff is a very central concept in everything, from social sciences to economics, from music to car industry, from computer networks to politics. But it is especially very important in computer science and maths, mainly because the decisions are solely based on facts and numbers instead of feelings and intuition. No excuses for giving false answers, it has to be the (most) right answer. Solving a simple problem, which has one right solution, should be effortless. But is there a most right way to find a compromise between many right solutions?</p><h4>What is a Tradeoff?</h4><p>Tradeoff is defined as a balance / compromise achieved between two (or more) adversarial but desirable features. It can be depicted as a deal negotiation between two (or more) companies, each having its pro’s and con’s, trying to find a compromise, which satisfies all parties.</p><p>From a mathematical point of view, it is just an optimization problem, given constraints. The fun part is, there may not always be a perfect solution, because each solution has its upsides and downsides. But there is always an optimal solution, which maximizes the upsides and minimizes the downsides.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*kdcxWRkho-N_MSfvKie1Mw.png" /><figcaption>Source: ml-science.com</figcaption></figure><h4>Real-life Examples of Tradeoff</h4><p><em>Counting the votes as always vs. switching to an electronic voting system</em>: Exponentially growing population favors electronic voting over manual voting, but if no more presidential elections expected in the next 5 years, it is useless.</p><p><em>Making minor updates to the bank database written in COBOL vs. reimplementing the database using more modern programming languages such as Java</em>: No changes should be made if everything is finely tuned in COBOL, but if the database requires major changes to fully function, it can be refactored or reimplemented using Java.</p><p><em>Allowing collision vs. implementing a prevention mechanism for collisions</em>: If it is very unlikely to have a collision in a system or it has just tiny consequences, it is economically a better decision, to implement nothing, but if it is very significant, a strict prevention mechanism should be implemented.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*53LzqkzuZ17KACtmkLK8Tg.png" /><figcaption>Source: bitxorbytes.home.blog</figcaption></figure><h4>Types of Tradeoff</h4><p><em>Space / Time</em>: Recalculating each time something is queried vs. caching it in lookup table the first time it is calculated and reusing it later.</p><ul><li><a href="https://bitalksbi.com/oltp-vs-olap-database-vs-data-warehouse">OLAP vs. OLTP</a>: OLAP (Online Analytical Processing) is a data processing method used for data exploration and analysis. OLTP (Online Transactional Processing) is a data processing method used for data storage and manipulation. In OLAP, the information is redundant and it takes a relatively short time to access data, but more space is needed. In OLTP, data is more difficult to access and more time is needed, because instead of the value, its shortcuts are saved, which reduces space usage.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*sQI0SU6d_ORSx7cJLgQfPg.jpeg" /><figcaption>Source: GalacticaSoft</figcaption></figure><ul><li><a href="https://www.geeksforgeeks.org/java-program-to-compare-two-objects/">Object Comparison</a>: A naive approach for comparing two instances of a Person class in Java would be comparing each attribute one by one. A better approach would be to concatenate the attributes in a string like “15-Andrew-Myview-Male” or “56-Chris-Dunkler-Male”, and storing it as the summary of instance at given time point. Comparing two different takes only one attribute and saves a lot of time, in exchange for storing a variable-length string inside.</li><li>Side Note for Object Comparison: It is no longer a tradeoff, if <a href="https://en.wikipedia.org/wiki/Hash_function">hashing</a> ( = irreversible reduction of data to a lower-dimensional latent space, which is almost perfectly unique) is applied in this situation. For example, the hash value of the instance is created by hashing the string using SHA-256 (complexity is O(n) where n is the length of the string), and it takes always 256-bit to store this. The hash collision ( = two different objects have the same hash value) is very unlikely to happen, so the object comparison works very efficient all the time.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*xNtzABoWjTptu8ISHctVBA.png" /></figure><p><em>Bias / Variance</em>: If you just capture the trend by not paying too much attention to details, you miss the important details. However if you pay too much attention to details, you miss the general trend.</p><ul><li><a href="https://machinelearningmastery.com/overfitting-and-underfitting-with-machine-learning-algorithms/">Underfitting / Overfitting</a>: We assume a machine learning model is the most accurate, when it is trained exactly in 500 epochs. The model accuracy increases steadily over the course of training till epoch 500, as long as it is still underfitted, because it actually learns the meaningful details. After epoch 500, the model is overfitted and it starts to decrease, because it pays too much attention to noise and misses the actual trend. Another downside of overfitting is that it is computationally exhausting to train a ML model so many times. That’s why early stopping is magical: It stops at some point if the trend will most likely drop.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*1G6Q9BzqO42vj5omzU4tMg.png" /></figure><p><em>Accuracy / Performance</em>: The less information stored, the more efficient resource management.</p><ul><li><a href="https://en.wikipedia.org/wiki/Principal_component_analysis#Intuition">PCA decomposition</a>: Given a <em>n x n</em> matrix and a desired number of components <em>k</em>, PCA algorithm calculates and makes a new matrix <em>n x k</em> out of the <em>k</em> most significant components. Basically, PCA filters the noise in data along with a tiny share of meaningful information. The new compressed matrix contains meaningful, yet incomplete information about the original matrix.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*C-vXqe4M7QgFU89SV2-DDg.png" /><figcaption>Source: Andrea Chello</figcaption></figure><ul><li><a href="https://en.wikipedia.org/wiki/Dropout">Dropout Technique</a>: In Machine Learning, a ML model tries to find the optimal parameters to minimize a loss (error) function, and it is called training. Using optimization algorithms, it gradually moves towards a global minimum. A ML model with e.g. dropout rate of 0.3, forgets 3/10 of the randomly chosen model parameters at each iteration. The dropout rate establishes the balance between the expected and randomized behavior of a ML algorithm. In case of being stuck at a local minimum, the models with a high dropout rate get easily out of the local minimum, but if the dropout rate is very high, it becomes more difficult to find the global minimum.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*iKQMG3wptZApAR3K7tc_FQ.png" /><figcaption>Srivastava, Nitish, et al. ”Dropout: a simple way to prevent neural networks from<br/>overfitting”, JMLR 2014</figcaption></figure><p><em>Compile-time / Run-time</em>: The more time spent in compiling data vs. the more data allocated in the run-time.</p><ul><li><a href="https://www.guru99.com/stack-vs-heap.html">Stack vs. Heap</a>: Stack and Heap are the two main data structures used in RAM. Stack stores local variables and function parameters, whereas Heap stores dynamically allocated variables. In general, Stack deals with data whose memory usage is fixed or can be estimated in compile-time, and Heap deals with the variable-length data whose memory usage is defined in run-time dynamically. But also, there are many overlapping use-cases of Stack and Heap, and it might be hard to find a compromise.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*d-yKUUbXQqWg5HPC_D0A2w.png" /><figcaption>Source: visualgdb.com</figcaption></figure><p>When creating an array / pointer in C, it can be done in two different ways:</p><p>Stack (The pointers are allocated in compile-time automatically and deallocated at the end, the physical address and memory usage of pointer cannot be modified):</p><p>Heap (the pointers are allocated and freed in run-time dynamically, one can also reallocate it with a different size and change the pointer):</p><ul><li>Classes vs. Instances: A class is a scheme for an object, which requires a fixed amount of space in Stack. An object is an instance of a class, which needs to be dynamically allocated in Heap, because it varies from code to code how many instances of a class is created. Java implementation of both:</li></ul><p>A class:</p><p>An instance of the class:</p><p><em>Data / Algorithm</em>: The more general an algorithm is, the more data it requires to compensate the lack of domain expertise.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*ZNEZoWEb3h88opR1V2vv8w.jpeg" /><figcaption>Created by me, <a href="https://medium.com/u/1c2f7a69a69e">Yamac Eren Ay</a></figcaption></figure><p><em>Naivety / Efficiency</em>: The more discoveries in a field, the more likely the boost in performance of an algorithm in exchange for simplicity.</p><ul><li><a href="https://www.programiz.com/dsa/dijkstra-algorithm">Dijkstra Algorithm</a>: Given a connected graph G=(V, E) with V nodes, finding the shortest path from a to b using brute-force has a O(V!) complexity. Djikstra algorithm takes advantage of the information that only the shortest paths yet from u to v is worth considering for each pair of nodes u and v, which decreases the overall complexity to O(V²). An even better algorithm favors the shortest distances using priority queues, which has an astounding complexity of O(V + E log V). The more discoveries are made in graph theory, the more likely a graph algorithm will be improved.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*7VTHTZyN3hK9Uz9ZLUQwQA.png" /><figcaption>Source: Nita Jonuzi</figcaption></figure><p><em>Recursion / Iteration</em>: Recursion is quite elegant, but sometimes iterative variants perform better, saving tons of recursive calls.</p><ul><li><a href="https://www.geeksforgeeks.org/depth-first-search-or-dfs-for-a-graph/">Depth-First Search</a>: Recursive implementation is pretty intuitive but requires a lot of recursive calls. Iterative implementation rather uses stacks as a data structure inside the program, and calling / returning is achieved by pushing / popping.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*yBRs2Cm-jrdmD8QfEA8tMA.png" /><figcaption>Source: An Moku</figcaption></figure><ul><li><a href="https://www.mathsisfun.com/numbers/golden-ratio.html">Golden Ratio</a>: Given two fibonacci numbers fib(n) and fib(n-1), where n is a very large natural number, the golden ratio is the division of fib(n) by fib(n-1). Calculating it using fibonacci means high computational expense and waste of time. The iterative variant is in that case very simple:</li></ul><ul><li><a href="https://www.cuemath.com/algebra/fibonacci-numbers/">Fibonacci</a>: Each Fibonacci number fib(n) is equal to the sum of the two previous fibonacci numbers (fib(n-1) and fib(n-2)). The most naive yet intuitive approach for calculating n-th Fibonacci number would be writing a function that works top-down and calculates n-th number. It is solved in an exponential time-bound because the subproblems overlap (<a href="https://www.geeksforgeeks.org/dynamic-programming/">Dynamic Programming</a>). In bottom-up approach, a linear time complexity is reached in exchange for space complexity O(N) using the memoization technique ( = caching the results in a lookup table or an array). One needs to add two previous numbers at each step to get the next number, but still, it can be improved using pure mathematics. An equivalent matrix form of this function is illustrated below:</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*gWYqN4ZkMcGZt2kr3OcVFg.png" /></figure><p>The first <a href="https://en.wikipedia.org/wiki/Eigenvalues_and_eigenvectors">eigenvalue</a> of the matrix on the left side is equal to the Golden Ratio. (Not a coincidence that the golden ratio is defined as the division of two Fibonacci numbers on the edge of infinity). Without matrix multiplication or looking up the second Fibonacci number, one can calculate the next Fibonacci number by multiplying a number with the Golden Ratio and rounding it to the next integer. (It works very well for n &gt; 5).</p><p>Now that we have a grasp of tradeoffs, let’s dive more into the concept of tradeoffs.</p><h4>How to Find the Optimal Balance?</h4><p>In order to figure out the optimal solution, we need to first define the total error function. Given f(x) and g(x) are the error functions of 2 factors in a tradeoff called A and B, the total loss function is defined h(x) = f(x) + c * g(x) where c is the penalty term for tuning the balance between A and B.</p><ul><li>If c is near zero, A is more significant than B, and f(x) is minimized more than g(x)</li><li>If c has a very large magnitude, A is less significant than B, and g(x) is minimized more than f(x)</li></ul><p>This technique is called Regularization. Finding the optimal c for a given h(x) is achieved by Lagrange Optimization.</p><p><a href="https://machinelearningmastery.com/a-gentle-introduction-to-method-of-lagrange-multipliers/">Lagrange Optimization</a>: An optimization technique, given a function f(x) and constraint functions g1(x), g2(x), …, gn(x), tries to minimize the total loss function h(x) = f(x) + c1 * g1(x) + … + cn * gn(x), not only based on the input values of x, but also the coefficients c1, …, cn which all define the significance of factors.</p><h4>How to Differentiate Between a Tradeoff and a Non-Tradeoff?</h4><p>If there are at least 2 variables in compromise, it is a tradeoff and it is an optimization problem. If only one variable called A is significantly more desirable than other variables B1, …, Bn, it is a non-tradeoff and it is a minimization / maximization problem.</p><ul><li>Let’s assume A is more significant than other factors B1, B2, …, Bn, and the total loss function h(x) is defined as f(x) + c1 * g1(x) + c2 * g2(x) + …+ cn * gn(x).</li><li>For each i between 1 and n (inclusively), ci should be approximately 0, because Bi is not as significant as A.</li><li>Therefore, h(x) is approximately equal to f(x). The global minimum of f(x) is the global minimum of h(x), and also the global optimum of h(x).</li></ul><p>A relationship is a non-tradeoff, if: The tradeoff of different factors is well optimized, if and only if the penalty of the most significant factor is minimized. This is when every company on the table has agreed to work together for the concerns of the biggest company. Best practices like:</p><ul><li>Choosing a Divide-and-Conquer algorithm over naive looping</li><li>Picking an efficient and easy graph algorithm instead of brute-forcing</li><li>Selecting Fast Fourier Transform over Discrete Fourier Transform</li></ul><p>are not to negotiate. Below are tradeoff graphs for circumstances 1 and 2:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*JUXM70dIQtwtyTYfUWB42Q.png" /><figcaption>Circumstance 1, X-axis is c (regularization parameter) | Y-axis is the overall loss function h(x) = f(x) + c * g(x)</figcaption></figure><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*n0Wpqh7-925Z_D4BChsJtg.png" /><figcaption>Circumstance 2, X-axis is c (regularization parameter) | Y-axis is the overall loss function h(x) = f(x) + c * g(x)</figcaption></figure><p>Improving an already existing algorithm and reducing the loss unconditionally is a good <em>non-tradeoff</em> decision .</p><p>Switching from one best algorithm to another best algorithm is a <em>tradeoff</em> decision. Depending on the current circumstances, a tradeoff decision can be good or bad. For example, it could have been:</p><ul><li>Space is very limited. The h(x) function is skewed directly along with space, algorithms with the lowest space complexity are favored. Let’s say there are just 8 bytes allocated for all function parameters, so a maximum of 2 integers can be allocated in each function (except return value). In case of calculating Fibonacci, a naive approach with exactly using 2 integers is the best choice.</li><li>Accuracy is very important. The h(x) function is skewed along with accuracy. Only the most accurate algorithms are favored. Let’s say there is a ML algorithm that can tell whether the car driver has speeded, if yes reads the car signs and marks it as “expected to pay the ticket”. In the case of a false decision, the error may have legal consequences. That’s why the volume of the training data, the time spent for training, technical expenses etc. are not as important as the success rate.</li><li>Time is very important. A website needs to be created in 3 weeks and 1 week extra is considered enough for testing. Hiring a very good team and working relentlessly may be worth paying huge expenses if this website is very important.</li></ul><p>Unless there is really a theoretical bound, the question, if there is always a “better” solution, is an undecidable problem itself.
