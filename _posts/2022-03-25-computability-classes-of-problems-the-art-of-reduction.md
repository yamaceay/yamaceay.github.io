This has mostly the following form:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*2RWX7DrCAtgVUxY09gkBXw.png" /></figure><p>In the code above, the only way the while loop is left is by setting the result to YES. Otherwise, there is no return value and the result is undefined till a YES instance is found. If only we prove that it is in a <em>infinite</em> loop, the result is NO.</p><p>We assume that the output is always a YES instance: <em>If it terminates</em>, it returns always YES (partially correct), but it is not known <em>if it always terminates</em> (not totally correct).</p><p>An interesting feature of SD problems is that we can list all outputs (lexicographically) because we know with guarantee that the inputs that are accepted are accepted.</p><p><em>CSD</em>: The same applies, but other way round. The rejected words are rejected for sure, but the still accepted words might be rejected in later iterations.</p><p><em>D</em>: A language is decidable, if there <em>exists</em> an algorithm, which is computable in finite steps for <em>every</em> input whether it is accepted or not. It is also the intersection of SD and CSD, because a decidable language is semi-decidable and co-semi-decidable at the same time.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*sN7xK8ebJZmFdlgUMvP_MA.png" /></figure><p><strong>Reduction Demystified</strong></p><p>When manufacturing a car, there is no need to reinvent the wheel, we can simply reuse other components produced by other companies to save us a lot of time (and space).</p><p>In simple terms, the reduction means reusing the part of an algorithm in another algorithm to reduce the number of problems. Given 2 different problems A and B. We show that we can rewrite A using B internally, also <em>reduce</em> A to B, also</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*bKiYdSiKEscHEdRtP79jQg.png" /></figure><p><strong>Types of Reduction</strong></p><p>To make it simple, we mean by default reduction <em>many-to-one</em> reduction. Many-to-one reduction means that there is no restriction so that the words mapped from A to B using a characteristical function can <em>overlap</em> on both sides.</p><p>It can be a reduction in terms of computability or complexity, depending on use case:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*A2zMQvpBDRMHLMY6yGnSIw.png" /></figure><p><strong>Example of Reduction</strong></p><p>For example, finding the maximum can be reduced to sorting problem:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*204wfQb0pW0loRw3JJW_7A.png" /></figure><p><em>Side-note</em>: Finding max is proven to have a lower complexity, which is an example that the reductions might not be useful in all cases.
