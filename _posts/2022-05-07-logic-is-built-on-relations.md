<h4>… and it is not the only one!</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*WT_5nmpmgu9OPDqvDT9KSQ.jpeg" /><figcaption>Source: <a href="https://wallpapercave.com/intelligent-wallpapers">https://wallpapercave.com/intelligent-wallpapers</a></figcaption></figure><h4>Logic in Simple Terms</h4><p>Logic is a very crucial computer science field that fuels the information technology industry.</p><p>A few important use-cases of logic:</p><ul><li>querying relational databases</li><li>filtering contents in email</li><li>decision-making of cars</li><li>constraint satisfaction problems</li><li>sudoku solving</li><li>finding an optimal solution to a game</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*begym-gs4czu6UWYrfSeqQ.png" /><figcaption>Source: <a href="https://wallpapercave.com/intelligent-wallpapers">https://wallpapercave.com/intelligent-wallpapers</a></figcaption></figure><p>There are different types of formal logic, which express a real-world problem in more formal syntax, such as:</p><p><em>Boolean Logic:</em> Boolean variables, junctors</p><p><em>First-Order Logic:</em> Universal set, quantification, predicates, relations, structures, and signatures</p><p><em>Second-Order Logic: </em>‘is-an-element-of’ relationship, quantification from any set</p><p><em>Higher-Order Logic:</em> …</p><p>The motto is: the higher the order of the logic, the more flexible it can be.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*YoO4S0vwgQSM9s-4wxaDcA.png" /><figcaption>Source: <a href="https://www.pega.com/de/insights/resources/pega-workforce-intelligence">https://www.pega.com/de/insights/resources/pega-workforce-intelligence</a></figcaption></figure><h4>Boolean Logic: Capabilities &amp; Limitations</h4><p>Most basically, Boolean Logic is the purest form of all logic. Computers are implemented using Boolean Logic and built on top of Boolean Logic gates, which use AND, OR, NOT internally.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*Fko1hTGojApRjKEfxNwXqw.png" /><figcaption>Source: <a href="https://www.researchgate.net/publication/357620048">https://www.researchgate.net/publication/357620048</a></figcaption></figure><p>To put it simply, Boolean Logic consists of the following elements:</p><p><em>Variables</em>: Information holders, which evaluate to either true (1) or false (0).</p><p><em>Junctors: </em>Operations, which define the most basic relationships between variables in formulas, such as AND, OR, NOT.</p><p><em>Formulas:</em> Arbitrarily complex information holders, which make use of variables and junctors to store meaningful information. A variable is an atomic formula (a 0-degree formula).</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*sFbSyXnRbrZbvhU2my1gug.png" /><figcaption>Source: <a href="https://www.researchgate.net/figure/The-computational-problem-A-20-variable-3-CNF-Boolean-formula-The-symbol_fig4_11467791">https://www.researchgate.net/figure/The-computational-problem-A-20-variable-3-CNF-Boolean-formula-The-symbol_fig4_11467791</a></figcaption></figure><p>Every (real-life) statement has its equivalent formula in Boolean Logic. But what about infinitely general assumptions?</p><p>All in all, infinity is a theoretical assumption used in mathematics and computer science to express various theories.</p><p>You can still make an assumption in Boolean Logic, regardless of how infinitely general it is. For example:</p><ul><li>“X”: There are infinitely many prime numbers.</li><li>“Z”: Every (possible) cake contains flour.</li></ul><p>It is clear that every problem boils down to Boolean Logic.</p><p>Simplistically, everything that Boolean Logic is not capable of, is defined as a new variable.</p><p>However, this makes Boolean Logic hard to work with, which is why some higher-order logics such as First-Order Logic are preferred for more complex tasks.</p><p>Since our brains are not programmed to think like machines, First-Order Logic is more easy-to-work-with and intuitive than Boolean Logic.</p><h4>What is First-Order Logic?</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*k0PGlIsTKEySHJIF6jIRcg.png" /><figcaption>Source: <a href="https://lara.epfl.ch/w/sav08/predicate_logic_informally">https://lara.epfl.ch/w/sav08/predicate_logic_informally</a></figcaption></figure><p>First-order logic is the boolean logic with the following extra features:</p><p><em>Universal sets</em>: It allows us to define a universe of numbers, letters, etc.</p><ul><li>Instead of creating binary variables for the numbers such as “x is 9”, “x is not 10”, we can now define x as 9 and not 10.</li></ul><p><em>Relations</em>: It is a set that stores a different ‘feature‘ of each element in a universal set.</p><ul><li>Instead of hard-coding every (binary) feature for each element as variables such as “x is a prime number”, “x is a Fibonacci number”, we now define a set of prime numbers / Fibonacci numbers, and check whether it contains.</li></ul><p><em>Predicates</em>: It extends the list of operations allowed in boolean logic such as AND, OR, NOT by arithmetical operations.</p><ul><li>Instead of hard-coding all possible results as variables such as “x + y is 5”, “z is negative”, we define the predicates x + y = 5 and z &lt; 0.</li></ul><p><em>Quantification</em>: It allows us to make (infinitely large) assumptions that iterate over each element in the universal set and selects/rejects using predicates.</p><ul><li>Instead of defining a conjunction of A_1, …, A_n ( = a big AND function), we define FOR ALL as universal quantifier, likewise instead of defining a disjunction of A_1, …, A_n ( = big OR function), we define EXISTS as existential quantifier.</li><li>When making a general assumption based on a universal set, it is a must to choose quantifiers instead of a big disjunction / conjuction, even if the universal set has a finite number of elements.</li></ul><p>In the next section, we proceed with <em>Signatures &amp; Structures</em>, the last feature of FO-Logic.</p><h4>Signatures &amp; Structures</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*2HBorycEI1d-__dhCWQ5Yw.png" /><figcaption>Source: <a href="https://levelup.gitconnected.com/essential-typescript-types-get-started-with-typescript-5e20a5106c90">https://levelup.gitconnected.com/essential-typescript-types-get-started-with-typescript-5e20a5106c90</a></figcaption></figure><p><em>Signature: </em>A set σ = {(c_i)_i, (f_j)_j, (R_k)_k} where:</p><ul><li>c_i as a constant</li><li>f_j: A → B as a function</li><li>R_k: (A, B) as a relation</li></ul><p>are declared, but not defined.</p><p>Relations are more expressive than functions and constants, which means every constant and function can be generalized as relations.</p><ul><li>A constant c is represented by a relation {c} where it only evaluates to true if and only if the element is c.</li><li>A function f : A → B is represented by a relation f : (A, B), since functions are defined as a special kind of relations.</li></ul><p>So every signature can be ‘relationalized’.</p><p>Defining structures below, we will only refer to the relational signatures.</p><p>Database perspective: Signature is the list of columns in database. Each column is a relation.</p><p>Object oriented perspective: A signature is an interface. A function is a method. A relation is an attribute. We can replace methods by an attribute storing every possible outcome of a method.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*WqdMra0dGUOo_DPGW9B9uA.jpeg" /><figcaption>Source: <a href="https://medium.com/the-renaissance-developer/sql-database-and-rails-9f519282ad57">https://medium.com/the-renaissance-developer/sql-database-and-rails-9f519282ad57</a></figcaption></figure><p><em>Structure: </em>Assuming σ ={(R_i)_i} is a (relational) signature. A σ-structure is a tuple 𝒜 = (A, (R^𝒜_i)_i) where:</p><ul><li>A is the universal set</li><li>R^𝒜_i is the implementation of R_i in 𝒜</li></ul><p>Database perspective: A structure is a database. Each row stores information about every unique combination of all elements. Each cell is mapped to a truth value, whether the elements in the given row are contained in the relation specified by the given column.</p><p>Object-oriented perspective: A structure is a class, which implements one or more interface(s). A universal set is an enumeration inside a class. All attributes (constants, relations) and methods (functions) are implemented, so it is not an abstract class. A column is a getter of attributes since we assume that methods are replaced by attributes. A row is an instance of a class, initialized with a unique combination of all elements. A cell is the output of the getter method of a row instance.</p><h4>[BONUS]How To Visualize Structures?</h4><p>Let’s assume σ ={(R_i)_i} is a relational signature.</p><p>Each relation R_i is a relation of arity d_i, which means R_i requires d_i input arguments. For simplicity, the relations are sorted ascending by arity d_i, so d_1 ≤ d_2 ≤ … ≤ d_n.</p><p>The question is: How to represent relations with different arity in the same database?</p><p>We can solve this problem by listing rows by standard lexicographical order “≼”. It is formally defined as:</p><p>Let a = (a_1, …, a_n), b = (b_1, …, b_m), a ≠ b.</p><p>“a ≼ b” is equivalent to (n &lt; m) ∨ ((n = m) ∧ (∃ i ∈ {1, …, n} : ((a_i &lt; b_i) ∧ (∀ j ∈ {1, …, i-1} : (a_j = b_j)))))</p><p>In other words: a comes first, if a has either fewer arguments, or it has the same number of arguments, but there is a number i between 1 and n, so that each a_j and b_j (until a_i, b_i) is equal, and a_i &lt; b_i.</p><p>Relations are sorted by arity. With this in mind, the unique combinations with length d_1, …, d_n can be listed in logical structure by standard lexicographical order.</p><p>Example: σ = {L_FALSE, L_TRUE, L_NOT, L_AND, L_OR} is the signature of boolean logic. We define a boolean logic structure 𝒜 = (A = {0, 1}, L_FALSE^𝒜, …, L_OR^𝒜) where:</p><ul><li>L_FALSE^𝒜 is an unary relation defined as {0} (likewise L_TRUE^𝒜 is a relation defined as {1})</li><li>L_NOT^𝒜 is a binary relation defined as {(a, b) | NOT a = b}</li><li>L_AND^𝒜 is a ternary relation defined as {(a, b, c) | a AND b = c} (likewise L_OR^𝒜 = {(a, b, c) | a OR b = c})</li></ul><p>The database of possible results looks like:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*418HJoIfTErNvvNwaWkuag.png" /><figcaption>1-ary relations: L_FALSE, L_TRUE; 2-ary relation: L_NOT, 3-ary relations: L_AND, L_OR</figcaption></figure><p>Finally, we achieved to illustrate a total relational representation of logical structures.</p><h4>Beyond This Article</h4><p>We addressed the issue with the Boolean Logic that it is a machine-level logic, and which is why we picked First-Order Logic, because it is much more similar to how we perceive the world.</p><p>We introduced the First-Order Logic and especially Signatures &amp; Structures, and we realized that a relational normal form for signatures exists, perhaps which is why First-Order Logic is sometimes referred as Relational Logic.</p><p>We found out that First-Order Logic shares some similarities with databases and object oriented programming, mainly because it is relational.</p><p>We also addressed the issue with relations of different arity and figured out how to visualize structures as a database using standard lexicographical ordering.
