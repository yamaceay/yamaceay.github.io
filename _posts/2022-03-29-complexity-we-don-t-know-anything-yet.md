You can check my all posts here:</p><ol><li><a href="https://yamaceay.medium.com/computability-turing-machines-formal-languages-6185f2dac94f">Computability — Turing Machines, Formal Languages</a></li><li><a href="https://yamaceay.medium.com/computability-classes-of-problems-the-art-of-reduction-d7f489e791f3">Computability — Classes of Problems, The Art of Reduction</a></li><li><a href="https://yamaceay.medium.com/complexity-introduction-da2035f72209">Complexity — Introduction</a></li><li><a href="https://yamaceay.medium.com/complexity-classes-and-their-limitations-6952455fa5a8">Complexity — Classes and Their Limitations</a></li><li><a href="https://yamaceay.medium.com/complexity-comparison-of-different-satisfiability-problems-e8f668167bab">Complexity — Comparison of Different Satisfiability Problems</a></li><li><a href="https://yamaceay.medium.com/complexity-we-dont-know-anything-yet-16cd8ed0e077">Complexity — We Don’t Know Anything Yet?</a> <strong>[THIS POST]</strong></li></ol><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*jan171LLrbMCtVI-ErEaPw.png" /></figure><p>Stephen Hawking has once said: “21st century will be the century of complexity”. All in all, it is still a theory, and it is true until proven false. However, we can definitely be sure that it improves in the right direction.</p><p>The advances in computer science has led to many interesting explorations but I want to point out the 2 important problems I find the most interesting:</p><ul><li>The Halting Problem</li><li>P != NP</li></ul><p>I will keep this post as short as possible and you can do your research, I’ll leave here some amazing discoveries:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*nSF0OFZV5xsjUeAOCEGa5w.png" /></figure><p><strong>The Halting Problem</strong></p><p><em>Philosophy:</em></p><ul><li>You cannot write a code which has total control over itself. You cannot write a code which makes a statement about its performance / output / internal feature or satisfies such criteria.</li></ul><p><em>Explanation:</em></p><ul><li>The question is, if the halting problem is decidable or not. This is strongly believed to be undecidable. You can find very clever proofs on the internet that a computer science with solved halting problem wouldn’t work.</li><li>We assume that a Turing Machine accepts only / halts at its own binary code. This problem is recognizable, since the Turing Machine would recognize its own binary code and halt / accept. But we wouldn’t have a proof that this Turing Machine wouldn’t accept other words, therefore it is not decidable.</li><li>In simpler terms: When a self-restricting statement like “TM accepts exact 5 words”, “TM halts on 0101”, “TM doubles the input” is the main criteria of a language, which TM operates on, it is most likely undecidable.</li></ul><p><em>Otherwise Consequences</em></p><ul><li>We could write a Turing Machine which decides whether its own binary code is given.</li><li>We could see that whether an even number is always equal to the sum of two prime numbers (Goldbach Conjecture).</li><li>We could find out that the total number of computable functions grows faster than natural numbers in the edge of infinity (Normally, according to <a href="https://en.wikipedia.org/wiki/Church–Turing_thesis">Church-Turing Thesis</a>, the number of computable functions grows as fast as natural numbers).</li><li>We might have to redefine the concept of infinity in the mathematics.</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*dg7YzZAgVPSMkbVhtLvgfA.png" /></figure><p><strong>Quines and Halting Problem</strong></p><p>Probably you have seen programs, which print themselves, called <a href="https://cs.lmu.edu/~ray/notes/quineprograms/">quines</a>. There is an interesting connection between quines and Halting Problem: Halting Problem indicates a code cannot control itself, but quines can print themselves; does a quine having “control” over itself solve the Halting Problem?</p><p>Programming codes can be represented by very large integers, that’s why the execution of programs can be seen as an integer function q where:</p><ul><li>n is the source code integer</li><li>q(n) is the output code integer</li></ul><p>Programming languages have different features and this function varies from language to language. In case of quine, the integers n and q(n) are coincidentally the same. This is actually not a function controlling its own output, it is a coincidence where the source code and the output code is the same (n = q(n)). So, this makes the Halting Problem still unsolvable.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*waW3vuHJ93k7qgJEwrsb0Q.png" /></figure><p><strong>P != NP</strong></p><p><em>Philosophy:</em></p><ul><li>If you don’t know about the whole system, you cannot find an optimal solution, as fast as, someone who knows the whole system.</li></ul><p><em>Explanation:</em></p><ul><li>You cannot really find an optimal solution to a problem in a system, where you have incomplete knowledge about and need to ask your neighbors who ask their neighbors …, as fast as you know the whole system and find an optimal solution to a problem.</li><li>Let’s assume we want to hard-code outcome of every circumstance, in other words we write down every “information” and we can access everything in polynomial time. Theoretically, we cannot know everything, the number of information grows to the infinity much faster than natural numbers, which is why implementing an efficient algorithm is still the most valid way for proving P = NP.</li></ul><p><em>Otherwise Consequences</em></p><ul><li>We could find the shortest path in Traveling Salesman Problem in a reasonable time without having visited every road.</li><li>We could implement a very efficient algorithm for any game with single-player where it searches for a possible solution as fast as a bot, which played all combinations of game previously and can tell the valid outcomes given circumstances.</li><li>We could find the most perfect boy- or girlfriend in a reasonable time without knowing everybody personally around the world, etc.</li><li>We could prove there is a polynomial upper time bound for many pseudopolynomial problems such as Knapsack and Subset Sum, which means those problems take only polynomial time regardless of the magnitude of the values.</li></ul><p><strong>P = NP: Not Yet But Might Be?</strong></p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*X4PEBjvYhiwjhxWe6fnmcw.png" /></figure><p>SAT is the first problem proven to be NP-complete and the most efficient algorithms known don’t prove P = NP. Therefore we search for other NP-complete problems starting from SAT and try to find an efficient algorithm which proves P = NP.</p><p>Let’s see an example below:</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*yQZhIf0KsLuHsMwFcyl6AA.png" /></figure><p><strong>Pseudopolynomial vs Polynomial: What Is The Difference?</strong></p><p>Given the input array A has n elements and largest number in A is equal to m. Let’s say we want to sort this array based on two different approaches, <a href="https://www.google.com/url?sa=t&amp;rct=j&amp;q=&amp;esrc=s&amp;source=web&amp;cd=&amp;cad=rja&amp;uact=8&amp;ved=2ahUKEwiX0ciS0ev2AhXZS_EDHXkoAqoQtwJ6BAgFEAM&amp;url=https%3A%2F%2Fwww.geeksforgeeks.org%2Finsertion-sort%2F&amp;usg=AOvVaw3_y6Z8i8j9OwGJydgCu_kE">Insertion Sort</a> and <a href="https://www.geeksforgeeks.org/counting-sort/">Count Sort</a>:</p><ul><li>Insertion Sort has a time complexity O(n²) where n is the size of the array</li><li>Count Sort has a time complexity O(n + m) where n is the size of the array and m is the largest value in that array</li></ul><p>Which one is better?</p><ul><li>If the largest value m has an upper limit, which is — on the edge of infinity — smaller than n², Count Sort is better, because the time complexity of Count Sort would be guaranteed lower than O(n²).</li><li>If the largest value m is always a multiple of n² on the edge of infinity, Count Sort and Insertion Sort slightly differ, because the time complexity of Count Sort would be quadratic too.</li><li>Otherwise, Count Sort is absolutely worse than Insertion Sort, when the largest value is arbitrarily bigger than a multiple of n² similarly. Let’s say m = c n⁹: Then the time complexity of Count Sort would be O(n⁹).</li></ul><p>Although Count Sort seems tempting at some point with its “linear” complexity, it is not explainable to the end user why it takes so long at worse cases. It is a very bad behaviour for a program to have an “arbitrarily bad” worst case, especially when we don’t see the numbers at all, for example in a machine-level code.</p><p><strong>Is Pseudopolynomial Complexity Good Enough for P = NP?</strong></p><p>Subset Sum, which is a NP-complete problem, has a pseudopolynomial complexity, which means that the upper time bound depends on the magnitude of input. This is considered as a huge problem, when taking general use cases into account, as we discussed above. So the answer is no, the pseudopolynomial is not enough (yet).</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*DHFPMyM3TDaHmVP9de_pnw.png" /></figure><p><strong>Is There A Hope?</strong></p><p>At first sight, it might be very similar to polynomial complexity, but it isn’t, when describing the worst case in the edge of infinity: The maximum value can be arbitrarily big and it is believed under assumption P != NP that there is no equivalent problem with polynomial upper time bound.</p><p>This improvement gives us still hope that such an algorithm may be out there about to be found out. An important example is 2-SAT: Unlike variations like SAT and 3-SAT, 2-SAT can be solved in polynomial time. The reason that there is no reduction from 3-SAT to 2-SAT is that the number of clauses in 2-SAT grows exponentially, so there is no way to store the meaningful information in 2-SAT efficiently.</p><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*omoAyeWt-0Tym31lgjQ4JA.png" /></figure><p><strong>How To Distinguish an Unrealistic Goal?</strong></p><ul><li><em>Sorting</em>: Naive approach is O(n²). Most efficient approach for any list is O(n log (n)) according to the Master Theorem. There are algorithms proven to be O(n log (log (n))) working in specific situations. Sorting in O(n) as fast as reading could work only if the list is almost sorted (max. a constant number of elements needs to be moved), but then it would not be a sorting algorithm anymore.</li><li><em>Sum</em>: Naive approach is O(n). Most efficient approach is O(log n), according to the Master Theorem. The only possibility of O(1) would be to guess the number without knowing every input, but we know that it is unrealistic, it is not a clever idea to try to find such a sum algorithm.</li><li><em>Matrix Multiplication</em>: Naive approach is O(n³). Multiplicating two matrices in O(n²) as fast as reading both of them seems unrealistic. Most efficient approach yet is O(n^{2.37}). We still believe there might be a more efficient time bound between O(n^{2.37}) and O(n²) which is realistic, but trying to find an algorithm operating in O(n²) would be probably waste of time.</li></ul><p><strong>Final Words</strong></p><p>Hereby I conclude my 6-part series “How to Explain Complexity Theory To Your Buddy”. The name of the series has a 100% real background story, I was explaining it to a friend who is deeply interested in the theory of computer science. Then I came to the realization that if I cannot explain it with simpler terms, that means I know nothing about the topic, it is also called Feynman Method.</p><p>This series contains all my findings and thoughts, but if you learn it seriously, you still need to do your own research.
