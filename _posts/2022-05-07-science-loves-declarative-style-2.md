In the next section, we will learn more about 3 main fields, for which functional programming fits better:</p><ul><li>Probability Theory</li><li>Relational Databases</li><li>Math Language</li></ul><h4>#1: Probability Theory</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*hrkJQPbLCTHftk1dRa6u6w.png" /><figcaption>Source: <a href="https://michael-franke.github.io/intro-data-analysis/Chap-03-01-probability.html">https://michael-franke.github.io/intro-data-analysis/Chap-03-01-probability.html</a></figcaption></figure><p>Notations:</p><ul><li>Ω is the set of all possible values for an experiment, it can be Ω = <strong>ℝ </strong>or Ω = ℕ. We assume that n = |Ω| is the number of elements in Ω.</li><li>X : Ω → <strong>ℝ </strong>is a random variable <strong>mapping</strong> each value of Ω to another set of real numbers. A shorthand set notation for X(w_i) = x_i ∀ i ∈ {1, …, n} is: X(Ω) = {x_1, …, x_n}.</li><li>A ⊆ Ω is an event set <strong>filtering</strong> each value based on a condition, it can be {w ∈ Ω | w ≥ 4}, {w ∈ Ω | X(w) ≥ 40}, {w ∈ Ω | ∃ x ∈ X(Ω) : X(w)= x}. Alternatively, we can define a characteristic function: I_A(w_i) = 1 if w_i ∈ A else 0, which marks the values that A contains as 1 and others as 0.</li><li>ℙ : Ω → [0, 1] is the probability function <strong>reducing</strong> the given set to its probability of happening.</li></ul><p>For example if we wanted to calculate ℙ(X(A) = x) for any x ∈ <strong>ℝ</strong>, we would start from the bottom and:</p><ul><li><strong>select</strong> A ⊆ Ω from the universal set Ω,</li><li>then <strong>map</strong> each element a ∈ A to x ∈ X(A),</li><li>then <strong>select</strong> a for which X(a) = x,</li><li>and finally <strong>summarize</strong> the resulted {X(A) = x} to a probability by counting the number of elements inside and dividing it by n.</li></ul><p>In this special case: Coding in functional style is easier.</p><h4>#2: Relational Databases</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*lbGKGnZ5v7BxPsQwxpBkCw.png" /><figcaption>Source: <a href="https://www.mysqltutorial.org/mysql-sample-database.aspx">https://www.mysqltutorial.org/mysql-sample-database.aspx</a></figcaption></figure><p>In SQL, relations are the key data structure.</p><p>Every answer is a relation.</p><p>If you have read my previous article on Logic is Built On Relations, you can find some hidden connections.</p><p>I found this online database <a href="https://www.w3schools.com/sql/trysql.asp?filename=trysql_asc">here</a>. collection of records, even if it is just a cell (see the 4th example).</p><p>Operations fit very well for MapReduce pattern.</p><h4>#3: Math Language</h4><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*HCuSGdZ_uLTbO3gEVNe6Ig.jpeg" /><figcaption>Source: <a href="https://www.pinterest.de/pin/507429083012585185/?amp_client_id=CLIENT_ID%28_%29&amp;mweb_unauth_id=%7B%7Bdefault.session%7D%7D&amp;amp_url=https%3A%2F%2Fwww.pinterest.de%2Famp%2Fpin%2F848154542306253786%2F">https://www.pinterest.de/pin/507429083012585185</a></figcaption></figure><p>In my opinion: If math language was written in a programming language, it would be more likely in Haskell than C.</p><p>I think you’ve read so far, so you have an idea of how does MapReduce pattern looks like in real-life use cases.</p><p>In this section, we will rather talk about the very little details that lead to the biggest conclusions.</p><p><em>Statelessness</em>: The defined functions (and variables) hold the same values regardless of the current line we are reading. That means, if we would debug a program written in an universal math programming language:</p><ul><li>We would not see a change in values of already defined variables jumping from line A to B.</li><li>The number of variables would increase continuously till we reach the end of the program.</li><li>The number of variables would not decrease at any time point.</li></ul><p><em>Statements using “”</em>: Note that the default notation for functions is prefix, e.g. f(a, b), but we can also use the infix notation for functions with 0, 1 or 2 arguments, e.g.:</p><ul><li>a “f” b ≙ f(a, b): 2 arguments</li><li>a “f b” ≙ f_{b}(a): 1 argument</li><li>“a f” b ≙ f_{a}(b): 1 argument</li><li>“a f b” ≙ f_{a, b}(): 0 argument (no variable outside the “” double quotes)</li></ul><p>With this in mind, every statement like “x is a number greater than 9” or “8 is greater than 80” are also functions with no arguments.</p><p>Very basic example of fibonacci numbers, showing the functionality of “”:</p><ul><li>We assume fib(n) calculates the n-th fibonacci number.</li><li>isFib : <strong>ℝ</strong> → {0, 1} is a function which identifies the fibonacci numbers.</li><li>It is defined as isFib(x) = ∃ i ∈ ℕ, i ≥ 2: x = fib(i-1) + fib(i-2).</li><li>Normally, we write in prefix notation: {x ∈ <strong>ℝ </strong>| isFib(x)}.</li><li>Converting it to infix notation, it looks like: {x ∈ <strong>ℝ </strong>| “isFib” x }.</li><li>If x is assigned e.g. 5, isFib(x) = isFib(5) becomes a variable.</li><li>Since isFib(5) is a variable, it does not have any extra variables outside the “” double quotes.</li><li>So isFib(5) becomes “5 is a fibonacci number” in human language.</li><li>So it makes sense to write {x ∈ <strong>ℝ </strong>| “x is a fibonacci number” }.</li></ul><p><em>No pseudocode</em>: In maths, it is a very rare case that an imperative pseudocode is written. There is no defined FOR or WHILE construct totally written in symbolic language. That’s why <a href="https://www.oxfordreference.com/view/10.1093/oi/authority.20110803122041931">WHILE language</a> is created.</p><p>A WHILE program for calculating the average of given set A:</p><ul><li>Arguments: a_1, …, a_n (Elements), n (Number of elements in the set)</li><li>Returns: m</li></ul><figure><img alt="" src="https://cdn-images-1.medium.com/max/1400/1*wcDby4rWihNN_LTXxqUJJw.png" /><figcaption>WHILE Programm</figcaption></figure><p>Now let’s look at the mathematical definition: Let n = |A| and a_1, …, a_n ∈ A, then m := (a_1 + a_2 + … + a_n) / n.</p><ul><li>a_1 + a_2 + … + a_n is a recursively defined function with start index = 1, step size = 2–1 = 1 and stop index = n.</li><li>If we would write it in prefix form, it would look like: +(a_1, +(a_2, …+(…, a_n))).</li><li>The prefix version could be executed in functional programming using reduce().</li><li>In this case, some function like →reduce(i ∈ ℕ, i≤ n, acc = 0 | a_i + acc) could perform very well.</li></ul><p><em>Is-an-Element-of Relationship:</em></p><p>n ∈ ℕ is not an objection to my conclusion. It means that n doesn’t really actually exist at all! When we define {i ∈ ℕ | “i is an even number”}, actually no such variable i exists. It is an abstraction for each number {2, 4, …}, and not a counter variable.</p><p>Likewise, in a statement like “Let n ∈ ℕ any natural number. Then P(n).” outside of a set, it is not a variable, it is an abstraction.</p><p><em>Inductive Definitions: </em>Recursion rather than iteration.</p><p>Defining a general boolean formula using an infinitely large WHILE-loop is possible, but most likely not a good idea. Instead, boolean formulas are defined using inductive definitions.</p><p>Let’s say that P(n) is a valid boolean formula, given n ∈ ℕ is any number.</p><p><strong>Recursion start </strong>— P(0) is a variable or truth constant, so it is a boolean formula.</p><p><strong>Recursion step</strong> — If P(n) is a valid formula, then P(n+1) is a valid formula, for each n ∈ ℕ, n ≥ 0:</p><ul><li>Assuming P(n) is a valid formula.</li><li>If P(n+1) is defined as NOT P(n), it is still a boolean formula.</li><li>If P(n+1) is defined as P(n) logically linked to a variable X by junctors such as AND, OR etc, it is a boolean formula.</li></ul><p><strong>Recursion end </strong>— {no end if the set in the recursion step is infinitely large}</p><h4>Beyond this Article</h4><figure><img alt=""
